# Claude helper for json-typedef-codegen C++ implementation

Purpose

- Provide detailed C++ guidance for development in the `cpp/` directory.
- Focuses on the high-performance JSON library and NAPI integration.
- For general project context, see [../claude.md](../claude.md).

Quick tasks

- **Build C++ (standard):** `mkdir -p build && cd build && cmake .. -DENABLE_SIMD_JSON=On -DENABLE_NLOH_JSON=On && make`
- **Build with tests:** Add `-DBUILD_TEST=On` to cmake command; run tests with `ctest`
- **Build with Nix:** `nix-shell && mkdir -p buildNix && cd buildNix && cmake .. && make`
- **Generate single-header:** `./scripts/make_single_header.sh` (outputs to `single-header/json_typedef.hpp`)

Build & Test (detailed examples)

```bash
# From cpp/ directory
# Standard build (both backends)
mkdir -p build && cd build
cmake .. -DENABLE_SIMD_JSON=On -DENABLE_NLOH_JSON=On
make

# With tests (GoogleTest required)
cmake .. -DENABLE_SIMD_JSON=On -DENABLE_NLOH_JSON=On -DBUILD_TEST=On
make
ctest --output-on-failure

# NAPI build (Node.js bindings)
# Requires node-gyp, node headers, matching Node.js toolchain
npm install && npm run build

# Nix environment (if nix-shell available)
nix-shell
mkdir -p buildNix && cd buildNix
cmake ..
make
```

Code Conventions

- **Language:** C++23 (GCC 13+, Clang 17+)
- **Naming:**
  - Classes: `PascalCase` (e.g., `JsonData`, `JsonReader`, `SpecWriter`)
  - Functions/methods: `snake_case` (e.g., `parse_json()`, `serialize_value()`)
  - Member variables: `snake_case_` (trailing underscore, e.g., `buffer_size_`, `current_index_`)
  - Namespaces: `CamelCase::Nested` (e.g., `JsonTypedefCodeGen`, `JsonTypedefCodeGen::simd`)
- **Error handling:** Use `std::expected<T, E>` aliased as `ExpType<T>` (defined in `include/common.hpp`)
  - Return `ExpType<T>` instead of throwing exceptions
  - Use helper macros for error propagation (check CMakeLists.txt for details)
- **Memory:** Prefer smart pointers (`std::unique_ptr`, `std::shared_ptr`); avoid raw `new`/`delete`
- **Indentation:** 4-space (enforced by editor settings)
- **Includes:** Use `"` for local headers, `<>` for system/external
- **Headers:** Guard with `#pragma once` (modern C++)

Architecture overview

- **JSON Data Model:** `JsonData` class encapsulates document tree; `JsonValue` represents individual nodes
- **Reader backends:**
  - SIMD JSON: high-performance via SIMD intrinsics (src/simd_json/)
  - Nlohmann JSON: standard C++ JSON (src/nlohmann_reader/)
  - Selection via `USE_SIMD_JSON` / `USE_NLOHMANN_JSON` compile flags
- **Writer backends:**
  - Standard (nlohmann): src/nlohmann_writer/
  - Streaming: src/stream_writer/ (for large documents)
- **NAPI Integration:** [src/napi.hpp](src/napi.hpp) provides Node.js bindings; [src/napi_reader/](src/napi_reader/) and [src/napi_writer/](src/napi_writer/) implement reader/writer for NAPI values
- **Single-header:** [single-header/json_typedef.hpp](single-header/json_typedef.hpp) — standalone, self-contained output for distribution (regenerated by script)

Dependencies & CMake options

- **External libs:** SIMD JSON, Nlohmann JSON (header-only by default; see shell.nix for versions)
- **For tests:** GoogleTest (automatically fetched if `-DBUILD_TEST=On`)
- **NAPI:** Node.js development headers (via napi-build-utils or npm)
- **CMake options:**
  - `-DENABLE_SIMD_JSON=On/Off` — include SIMD backend (default: On)
  - `-DENABLE_NLOH_JSON=On/Off` — include Nlohmann backend (default: On)
  - `-DBUILD_TEST=On/Off` — build GoogleTest suite (default: Off)
  - At least one backend (`SIMD` or `NLOHMANN`) must be enabled

Common pitfalls (C++ specific)

- **No single backend enabled:** CMake fails if both `-DENABLE_SIMD_JSON=Off -DENABLE_NLOH_JSON=Off`. Always enable at least one.
- **Stale build artifacts:** Delete `build/` or `buildNix/` before switching CMake options or toolchain.
- **NAPI toolchain mismatch:** Node.js version, npm installed version, and C++ compiler must align; check `node --version` and npm version before NAPI build.
- **ExpType usage:** Always propagate errors with `ExpType`; avoid throwing exceptions in new code.
- **std::expected C++23 feature:** Older C++ standards require compatibility shim (currently C++23 enforced).

Integration with Rust codegen

- Rust CLI ([crates/target_cpp/](../crates/target_cpp/)) generates C++ code using templates
- Generated C++ code uses this C++ library as a build dependency
- Single-header output can be distributed alongside generated code for easy integration

Notes for AI assistants

- When modifying C++ code, ensure changes respect the Error handling pattern (`ExpType<T>` returns, no exceptions)
- Test changes with both SIMD and Nlohmann backends enabled (see quick tasks above)
- For new reader/writer backends, follow the pattern in existing backend dirs (src/simd_json/, src/nlohmann_reader/)
- If adding NAPI functionality, test with `npm test` in [cpp/](cpp/) after build
- Single-header generation is a distribution step; do not manually edit [single-header/json_typedef.hpp](single-header/json_typedef.hpp)
